How to read this report

Paired design. A "pair" is one back-to-back run of variant A and variant B (order randomized per pair). The within-pair difference cancels common-mode noise (machine load, cache state, network jitter) — the only thing that changes inside a pair is the feature flag. The unit of analysis is the per-pair delta.

Why a series of N pairs. One pair gives one delta; with N pairs we get a distribution of deltas and can quantify uncertainty. The headline numbers below are the mean delta across the N=20 pairs; the CI quantifies how confident we are in that mean.

Bootstrap CI. 95% confidence interval computed by resampling the 20 per-pair deltas (and the latency points within each pair) 5000 times with replacement. If the interval excludes zero, the effect is unlikely to be noise.

Counter snapshots. MySQL SHOW GLOBAL STATUS is snapped at the start and end of each arm; the per-counter delta is divided by the number of alerts offered in that window. See the Counter delta section for details.

Notes

  • Steady-window analysis only: warmup (30s) and drain (30s) are excluded, so the percentiles reflect server behaviour at stable load.
  • p99 is noisier than p50/p95 at modest N; if its CI crosses zero we report it as "not resolved at this N", not as evidence against the effect.
  • Absolute milliseconds depend on hardware, MySQL transport and pool size. The sign of the delta and the +1 SELECT-per-alert counter are invariant across environments; the millisecond magnitude is not.
